# CommitmentOS

CommitmentOS turns business conversations into tracked commitments so teams can follow through on what they promised.

This repository is being built in dependency-ordered increments. The current implementation establishes the application runtime, quality gates, PostgreSQL foundation, email/password authentication, workspace membership management, reusable workspace authorization guards, an authenticated responsive application shell, the commitment persistence/lifecycle/workspace API, immutable commitment and workspace-administration audit history, a workspace-scoped commitment inbox, and commitment detail with a read-only commitment audit timeline. Provider integrations, message ingestion and extraction, and their automated product workflows remain later stages.

## Stack

- Node.js 22 and npm
- Next.js App Router, React, and TypeScript
- Better Auth with Zod input validation
- PostgreSQL with Drizzle ORM and Drizzle Kit migrations
- Vitest, ESLint, and Prettier

## Prerequisites

- Node.js 22 (see `.nvmrc`)
- npm 10 or later
- Docker Compose and Docker, for the included local PostgreSQL service

## Local development

```bash
npm ci
cp .env.example .env
docker compose up -d postgres
npm run db:migrate
npm run db:check
npm run dev
```

The landing page can start without PostgreSQL, but registration, sign-in, sessions, and the protected `/app` route require a reachable PostgreSQL instance. Before using the app outside local development, replace `BETTER_AUTH_SECRET` with a unique secret generated by `openssl rand -base64 32` and set `BETTER_AUTH_URL` to the canonical HTTPS origin.

Open <http://localhost:3000> after the development server starts. Use `/signup` to create an account and `/login` to sign in. Authenticated clients can create/list workspaces, list workspace members, perform owner-only membership administration, and use workspace-scoped commitment list/create/read/update endpoints; see [workspace behavior](docs/workspaces.md) and [commitment behavior](docs/commitments.md) for routes and authorization rules.

## Quality checks

```bash
npm run format:check
npm run lint
npm run typecheck
npm test
npm run build
npm run test:integration
npm audit --audit-level=moderate
```

`npm run test:integration` requires the database migrations to have been applied and a production build to exist. Use a dedicated local/CI test database: the script creates and removes temporary fixtures. It starts a local Next.js server and exercises authentication and logout, the authenticated application shell and membership-validated workspace selection, workspace membership and authorization, commitment persistence constraints, tenant-scoped commitment API and audit-history access, immutable audit records, atomic mutation/audit writes, and lifecycle transitions against PostgreSQL.

## Database migrations

Add application tables under `src/db/schema/`, then generate and review a migration:

```bash
npm run db:generate -- --name=describe-change
npm run db:migrate
```

The `commitmentos` PostgreSQL schema is reserved for application tables. Do not place credentials in source control; `.env.example` contains local-only values.

## Authentication scope

COM-104 uses Better Auth's email/password and database-session support. Passwords use Better Auth's built-in scrypt hashing; session cookies are HttpOnly and SameSite by default and Secure in production. Sign-up does not automatically establish a session, and duplicate-account registration receives a generic response to reduce account enumeration. Email verification, account recovery, and OAuth providers remain tracked follow-up work. COM-105 adds workspace membership, COM-106 adds reusable session/membership/role guards, COM-107 adds owner-only administration for existing registered accounts, COM-108 adds commitment persistence, and COM-109 adds the commitment lifecycle transition service. Email invitations and pending invites remain out of scope. COM-110 adds the workspace-scoped commitment API, COM-111 adds immutable audit history for consequential commitment mutations, and COM-112 adds the authenticated app shell with server-validated workspace selection. See [ADR-0002](docs/adr/0002-authentication.md) for the authentication decision, [workspace behavior](docs/workspaces.md) for tenant scoping and shell behavior, and [commitment behavior](docs/commitments.md) for the current aggregate and lifecycle scope.

## CI

GitHub Actions runs formatting, lint, TypeScript checks, dependency audit, unit tests, PostgreSQL migrations/smoke checks, a production build, and end-to-end authentication/logout, workspace authorization and switching, commitment API, lifecycle, and audit-history checks against an ephemeral PostgreSQL service.
